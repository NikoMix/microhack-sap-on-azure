## What the labs use

The microhack uses **100% GitHub Copilot** — no bespoke agent runtime, no inference infrastructure.
Everything runs inside VS Code / GitHub Codespaces through three built-in mechanisms:

| Mechanism            | Path                                  | Purpose                         |
| -------------------- | ------------------------------------- | ------------------------------- |
| Custom agent         | `.github/agents/moduleb-lab-coach.md` | Persistent teaching persona     |
| Skill / prompt files | `.github/prompts/*.prompt.md`         | Reusable, parameterised tasks   |
| MCP servers          | `.vscode/mcp.json`                    | Live Azure + GitHub data access |

<Aside type="tip">
  Pupils **use** these Copilot capabilities during labs — they do not build their own agents. That
  keeps the focus on Module B outcomes rather than agent engineering.
</Aside>

## Custom agent — Module B Lab Coach

**File:** `.github/agents/moduleb-lab-coach.md`

The **Module B Lab Coach** is the single persistent agent used across all six labs. It is tailored
for SAP Basis consultants who are newer to Azure and behaves as a patient step-by-step instructor.

### Key behaviours

- **Explains AND performs** — never says "you could run"; runs the command, shows the output, and
  explains what it means and how it maps to the Module B control being worked.
- **Evidence-first** — before completing any task it asks: "What artefact does the auditor need?"
  and produces it with the correct file name (see naming convention below).
- **Uses MCP actively** — queries Azure resources via the Azure MCP server and repo context via the
  GitHub MCP server; never hallucinates resource names.
- **Invokes skills** — delegates complex generation tasks (case study, HLD, runbook, etc.) to the
  dedicated prompt-file skills listed below.

### Module B control mapping

| Control | Lab | Description                            | Primary evidence         |
| ------- | --- | -------------------------------------- | ------------------------ |
| B.1.1   | C1  | SAP on Azure implementation capability | Case study + HLD         |
| B.2.1   | C3  | ACR performance (SAP-eligible spend)   | Annotated ACR report     |
| B.2.2   | C4  | Customer diversity (≥ 3 customers)     | Customer cross-reference |
| B.3.1   | C5  | SAP-on-Azure skilling                  | Skilling plan            |
| B.4.1   | C6  | Audit readiness                        | Evidence index           |
| B.4.2   | C6  | Customer onboarding                    | Operational runbook      |

### Invoke the agent

In any Copilot Chat window (VS Code or Codespaces):

```
@moduleb-lab-coach walk me through C1
```

```
@moduleb-lab-coach help me produce B.2.1 ACR evidence
```

## Skills (prompt files)

Each skill is a self-contained `.prompt.md` file in `.github/prompts/`. Skills can be invoked
directly with `#skill-name` in a Copilot Chat with the agent, or standalone.

### Evidence naming convention

Every artefact produced by a skill follows:

```
[ControlRef]_[DocumentType]_v[N].pdf
```

- **ControlRef**: `B11`, `B21`, `B22`, `B31`, `B41`, `B42`
- **DocumentType**: PascalCase descriptor (e.g. `CaseStudy`, `HLD`, `ACRReport`)
- **N**: integer version, starting at 1

Artefacts are saved under `labs/Module B/B[ref]/`.

## MCP servers

**Config file:** `.vscode/mcp.json`

Two MCP servers are pre-configured for Codespaces. Secrets come from environment variables — see
`.env.example` for the required names. **Never commit a real `.env` file.**

### Azure MCP server

Gives Copilot live access to your Azure subscription: resource groups, VMs, cost management, ACSS
deployments, Azure Monitor for SAP, Key Vault secrets URIs, and more.

```jsonc
// .vscode/mcp.json (excerpt)
"azure": {
  "type": "stdio",
  "command": "npx",
  "args": ["-y", "@azure/mcp@latest", "server", "start"],
  "env": {
    "AZURE_SUBSCRIPTION_ID": "${env:AZURE_SUBSCRIPTION_ID}",
    "AZURE_TENANT_ID": "${env:AZURE_TENANT_ID}"
  }
}
```

**Required env vars:** `AZURE_SUBSCRIPTION_ID`, `AZURE_TENANT_ID`
(optionally `AZURE_CLIENT_ID` + `AZURE_CLIENT_SECRET` for service principal auth;
otherwise `az login` interactive auth is used).

**Test:** In Copilot Chat, type `@azure list my resource groups` — the agent should return your
subscription's resource groups without leaving the editor.

### GitHub MCP server

Gives Copilot access to repo metadata, issues, pull requests, and file contents from
`NikoMix/microhack-sap-on-azure`. Used by the lab coach to fetch Bicep templates, lab READMEs,
and issue context during exercises.

```jsonc
// .vscode/mcp.json (excerpt)
"github": {
  "type": "stdio",
  "command": "docker",
  "args": ["run", "-i", "--rm", "-e", "GITHUB_PERSONAL_ACCESS_TOKEN",
           "ghcr.io/github/github-mcp-server"],
  "env": {
    "GITHUB_PERSONAL_ACCESS_TOKEN": "${env:GITHUB_TOKEN}"
  }
}
```

**Required env var:** `GITHUB_TOKEN` (auto-set in Codespaces; for local dev create a PAT with
`repo` + `read:org` scopes).

**Test:** In Copilot Chat, type `@github list open issues in NikoMix/microhack-sap-on-azure`.

### Loading MCP servers in Codespaces

1. Open the repository in a Codespace — the devcontainer installs all prerequisites automatically.
2. Copy `.env.example` → `.env` and fill in `AZURE_SUBSCRIPTION_ID` and `AZURE_TENANT_ID`.
3. Reload the VS Code window (`Ctrl+Shift+P` → **Developer: Reload Window**).
4. In Copilot Chat, verify: `View > MCP Servers` should show **azure** and **github** as running.

<Aside type="caution">
  MCP servers start lazily (on first use). If the first query times out, wait 10 seconds and retry.
  If they still fail, check that `.env` is populated and the Codespace has been reloaded.
</Aside>

## Mock datasets (tools/data/)

The generators in `tools/` produce **deterministic, seed-42 datasets** that make all lab exercises
reproducible without a live SAP system.

| File                            | Description                                                     | Used by        |
| ------------------------------- | --------------------------------------------------------------- | -------------- |
| `tools/data/sap-landscape.json` | SAP inventory: 5 systems, 5 customers, Azure resources, network | C1, C4, C5, C6 |
| `tools/data/consumption.csv`    | 3-month Azure spend (69 rows, ≈95% SAP-eligible)                | C3             |
| `tools/data/consumption.json`   | Same data as structured JSON                                    | C3             |

To regenerate (e.g. for a different classroom seed):

```bash
node tools/generate-sap-landscape.js --seed 42
node tools/generate-consumption.js --seed 42
node tools/validate-datasets.js   # should report 29 passed, 0 failed
```
